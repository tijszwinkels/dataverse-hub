The five stages

1 Design — define the type & 8 decisions Complete

Pulled the dataverse root node, read the instructionGraph001 spec, surveyed the existing TOML-based shared-realm implementation, and designed a new graph-native SHARED_REALM type. Locked all 8 design decisions with you.

  • 1 Realm identity: explicit content.realm
  • 2 Member refs: pubkey-only (offline-friendly)
  • 3 Ownership: prefix rule {pubkey}.
  • 4 Canonical object: UUIDv5 hash of realm name
  • 5 Revocation: edit members in higher revision
  • 6 Propagation: global via dataverse001
  • 7 Precedence: graph authoritative, TOML override
  • 8 Naming: type:"SHARED_REALM", relation "member"

2 Deterministic addressing layer (realm.RealmID / RealmRef) Complete

Implemented UUIDv5 hashing so any hub can compute the canonical ref {owner}.{uuid_v5(NS, realm)} without a lookup table. Verified byte-for-byte interoperable with Python's uuid.uuid5. Code review run; all findings fixed (empty-name bug, parser hardening, edge-case tests).

3 Graph membership reader — realm/graph.go Complete

Implemented GraphSharedRealms + ParseSharedRealm: parses SHARED_REALM objects, validates the type contract (owner-prefix rule, signer==owner, id == RealmID(realm)), extracts member pubkeys from relations.member, and exposes the same read API as the TOML SharedRealms. Higher revision wins; ties broken deterministically. All tests pass.

Code: realm/graph.go · realm/graph_test.go

Wired the graph reader into the hub end-to-end. realm.RealmResolver interface + Merged (graph ∪ TOML) combiner; storage.Index ingests SHARED_REALM objects and exposes Resolver(); CanRead / ValidateRealmsForPut / GET /auth/realms consult the merged resolver; PUT enforces the full type contract. Integration tests cover PUT accept/reject, member read / non-member 404, revocation by edit, and /auth/realms.

  • realm.CanRead / ValidateRealmsForPut consult merged source (graph + TOML)
